# 反弹 shell / 权限维持应急响应

## 事件特征（分诊依据）

- EDR 报「反弹 shell」告警，且持续不断产生（可能是定时任务）
- 计划任务/启动项里发现反弹命令（bash -i、nc、whoami、ifconfig）
- 隐藏的权限维持（ssh 公钥、后门账号、隐藏计划任务文件）

## 排查要点

1. **反弹命令定位**：EDR 告警里的反弹地址（内网 IP + 公网 IP）、执行命令（whoami/ifconfig 等）。
2. **计划任务深挖（关键）**：
   - `crontab -l` 常规查询看不到，但日志显示不停执行 → 查 `/etc/cron.d` 等目录
   - **CentOS 对 cron.d 文件格式要求宽松**，会把非标准文件（如 cron.tar）也解析执行
   - 解压/查看可疑文件内容，匹配反弹 shell 命令
3. **权限维持手段汇总**：
   - 计划任务反弹 shell
   - ssh 公钥后门（/root/.ssh/authorized_keys）
   - 后门账号（/etc/passwd 新增 uid=0）
   - 启动项/服务自启动
   - 打包删除原文件伪装（history 里搜打包/删除操作）
4. **入口点溯源**：
   - redis 未授权访问 → 拿权限后加计划任务维持
   - 历史命令里「攻击者打包并删除原文件进行权限维持」的操作记录
5. **历史残留判断（高频）**：
   - 计划任务创建时间 ↔ 历史演习时间（如 22 年 HW 7月28日）吻合
   - 回连 IP 与历史应急报告相同
   - 装了新 EDR 才产生告警 → 旧痕迹，非近期入侵

## 典型攻击路径

```
redis 未授权访问漏洞
  → 获取服务器权限
  → 添加隐藏计划任务（反弹 shell）权限维持
  → 外连跳板机/公网 IP
  → （历史残留：装 EDR 后才告警）
```

## 处置建议

1. 删除恶意计划任务文件（如 /etc/cron.d 下 cron.tar）、结束相关进程
2. 更新/配置 redis，防止未授权访问（禁用高危命令、绑 127.0.0.1、设密码）
3. 清理 ssh 公钥后门、后门账号
4. 全盘扫描、装 EDR
5. 网络隔离/ACL、封堵高危端口

## 报告要点

- 事件分析重点：反弹命令内容、计划任务深挖过程（常规查不到但日志在跑）、入口点
- 总结判断是否历史残留（对比历史报告时间线）
- 建议对应根因：redis 未授权、历史未清理

## 真实案例速记

- **中航供应链反弹shell**：EDR 报 172.20.10.180 反弹 shell 到 172.20.10.90（内网）和 120.78.236.185（公网）。计划任务创建时间 2022-07-28（22年HW），`/etc/cron.d` 发现 cron.tar（CentOS 解析宽松导致执行）。入口：redis 未授权。定性：22 年 HW 残留，装 EDR 后才告警。
