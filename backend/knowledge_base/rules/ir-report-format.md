# 应急响应报告格式（唯一格式）

所有应急响应交付报告都按这个六段结构写。这是从 80+ 份真实报告蒸馏出的标准结构。

## 报告骨架

```
一、相关说明
    1.1 客户信息
    1.2 应急人员信息
二、事件概述
三、事件分析
四、事件总结
五、安全建议
```

> 报告头部可加「适用性声明」「版权声明」「版本变更记录」，这是厂商标准模板，按客户要求可简可繁。**客户名、联系人、人员姓名、联系方式一律用占位符，不写真实信息**。

## 一、相关说明

- 客户信息：客户名称、联系人（脱敏）
- 应急人员信息：处置人员、所属部门、处置时间、处置方式（现场/远程）

## 二、事件概述

一句话讲清：**什么时间、谁发现、什么现象、影响什么、来源是什么**。

要素齐备的范例：
> 「2026年5月17日8点，教育部信息中心监测发现经费监管事务中心出现大规模数据库用户锁定事件。接报后立即现场排查。经查，实际被攻击系统为捐赠配比系统，攻击者利用应用系统任意文件读写漏洞写入 webshell，并在内网横向时暴力破解公共 Oracle 数据库触发用户锁定机制，导致业务中断。」

要点：
- 时间（精确到日/时）
- 告警来源（态势感知/EDR/云监控/上级通报/用户上报）
- 现象（挖矿/勒索/webshell/锁定/被删…）
- 影响范围（单台/多台/网段/业务系统）
- 处置方式（现场/远程）

## 三、事件分析

**这是报告主体**。按三线排查展开，每条结论要有证据支撑。

结构：
1. **攻击路线图**（有就画，文字版即可）：
   > 攻击者 → [入口漏洞] → 入口主机 → [横向] → 目标主机 → [行为]
2. **逐主机排查详情**（多主机时按 IP 分小节）：
   - 排查了哪些项（进程/网络/启动项/计划任务/账号/日志）
   - 每项结论 + 关键证据（命令输出、日志片段、文件 MD5、时间点）
3. **样本/日志分析**（如涉钓鱼附件、webshell、木马样本）：
   - 样本 MD5、沙箱/VT 结果、释放行为、回连 IP、持久化方式

写作要求：
- **证据导向**：每条「结论」都要跟「证据」（日志、文件、时间戳）
- **时间线对齐**：关键动作都要有精确时间，用于后续溯源
- **区分「确认恶意」与「疑似/正常」**：误报项明确写「无异常/正常业务」

## 四、事件总结

**结论 + 攻击路径时间线**。

必含：
1. **事件定性**：确认失陷 / 误报 / 历史残留
2. **攻击路径**（能串就串完整链）：
   > 例：「攻击者于 6月28日通过 jeecg 任意文件上传漏洞打入 webshell 拿下 172.20.10.140，随后以该机为跳板利用 NC BshServlet 远程命令执行漏洞拿下 172.20.10.30 上传 webshell。」
3. **入口点**：定位不到要说明原因（日志被删 / 时间久远 / 无法访问）
4. **影响面**：数据是否泄露、业务是否受损

高频结论类型：
- 真实入侵（入口明确）
- 历史演习/入侵残留（22年HW痕迹、装EDR后才暴露）
- 误报（DNS解析、SMB心跳、漏扫脏数据）

## 五、安全建议

**与根因一一对应**，不是套话。按根因列：

| 根因 | 对应建议 |
|------|---------|
| 弱口令 | 改强口令（8位以上含大小写数字特殊字符至少3种）、删无用账号、SSH密钥认证、限制登录尝试 |
| Web 漏洞/中间件漏洞 | 打补丁、升级组件（NC/蓝凌OA/Shiro/jeecg）、修复漏洞接口 |
| 未打系统补丁 | 打 MS17-010 等补丁（不打会二次感染）、关 SMB 端口（135/137/139/445） |
| 钓鱼/社工 | 安全意识培训、不点未知附件/链接 |
| 工具投毒 | 官网下载、用前查杀、本地不存密码本 |
| 无终端防护 | 装 EDR/杀软、全盘查杀、应用控制 |
| 内网穿透/违规外联 | 禁 ZeroTier/花生壳/翻墙、拆私自组网 |
| 无日志审计 | 部署全流量/日志审计、留存病毒样本 |

高频通用建议（按需取用）：
- 数据备份（离线/异地/云备份）
- 网络隔离/ACL、封堵高危端口、最小化服务暴露
- 封禁恶意 IP/域名（双向）
- 定期漏洞扫描、渗透测试、代码审计

---

## 交付节奏

1. **先给结论摘要**：事件定性 + 攻击路径 + 关键建议，让客户/用户先看懂
2. **再出全文**：按六段结构补齐
3. 报告前检查红线：敏感信息脱敏、不可逆操作标注「待确认」
