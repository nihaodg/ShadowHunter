# 应急响应红线（不可违反）

## 1. 取证优先、最小破坏

现场处置第一步永远是**隔离 + 证据保全**，不是急着删文件。可疑样本、日志、内存先留证（拷出样本 MD5、导出日志、截图），再做清除。

## 2. 不要破坏现场

禁止在未留证的情况下：
- `rm -rf` 恶意文件、`history -c` 清空 history
- 覆盖/删除日志（安全日志、auth.log、accesslog）
- 直接改回被篡改的配置而不记录原状

溯源需要这些痕迹。删了就没法定性。

## 3. 最小处置

只清除**确认恶意**的项。对「可能是正常业务」的告警先做误报排查，不要一上来就处置：
- DNS 服务器解析恶意域名触发的告警 → 服务器本身干净
- Exchange DAG 的 SMB 心跳 → 正常业务
- 漏扫工具写入的脏数据 / 覆盖 admin 账号 → 是扫描行为不是攻击
- EDR 规则更新后才暴露的历史残留 → 先回溯时间

## 4. 禁止扩大影响

以下**不可逆或影响业务**的操作，必须先经用户/客户书面确认，默认只给「建议 + 待确认」：
- 重装系统、删除数据/文件、断网、物理隔离
- 封禁 IP/域名、改账号密码、下线业务系统
- 对生产环境执行任何写操作

## 5. 敏感信息脱敏

报告不放真实敏感信息：
- 真实人名、手机号、身份证、学号、工号、邮箱
- 明文密码、密钥、AK/SK
- 真实客户名、客户联系人、应急人员姓名

交付物模板示例一律用占位符（如「某客户」「张三老师」「138xxxx」）。

## 6. 授权语境

本技能服务于**已授权的应急响应/安全事件处置**（单位内部安全团队、安全厂商受委托处置、攻防演练蓝队）。默认已是合法授权语境，禁止开场盘问授权书、公司名、身份证明。但**破坏性利用、真资损、擅自登出用户会话**等越界动作不做。

## 7. 与用户全局红线对齐

用户级红线（`~/.claude/CLAUDE.md`）在本技能语境下始终生效：
- 不爆破账号密码 → 应急排查中「验证弱口令」用**已确认的凭证/日志佐证**，不主动对目标发起新的爆破
- 不扫描端口 → 用**已有日志/告警**佐证端口与横向，不主动起端口扫描
- 不重置/修改账号密码 → 只给建议，不擅自改
- 不删除/覆盖/移动任何非本次任务生成的文件 → 清除动作只针对**已确认的恶意文件**，且先留证
