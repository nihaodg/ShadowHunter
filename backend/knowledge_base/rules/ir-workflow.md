# 应急响应总流程（六阶段）

应急响应不是「上机查一圈」，而是固定节奏。每个阶段有明确的动作和退出条件。

## 阶段 ①：接报定级

**目标**：搞清楚「谁报的、什么现象、影响范围、时间窗口」，分诊出事件类型。

要问清 / 要确认的要素：
- **来源**：谁报的（安全设备告警 / 运维 / 上级通报 / 用户自己发现）？
- **现象**：CPU 占用高？文件被加密？异常外联？网页被挂马？登录失败？
- **时间窗口**：首次异常是什么时候？持续多久？
- **影响范围**：单台还是多台？涉及哪些网段/业务？
- **已有告警**：安全设备（态势感知/EDR/APT/WAF/云监控）报了什么？攻击 IP、目的 IP、告警类型？

**产出**：一条「事件概述」一句话 + 一个分诊结论（对 SKILL.md 分诊表）。

> 定级时注意：安全设备告警 ≠ 失陷。先保持怀疑，用误报排查排除后再定性。

## 阶段 ②：隔离保全

**目标**：控制扩散 + 留下证据。**先留证再动**。

动作（按需，不可逆的先确认）：
1. **隔离**：受影响主机断网 / EDR 隔离 / 物理隔离。防勒索病毒、蠕虫（永恒之蓝）继续扩散。
2. **证据保全**（永远先做）：
   - 可疑文件：拷出样本 + 记 MD5/SHA256 + 记录路径和文件时间
   - 日志：导出安全日志、auth.log、accesslog、history（**先备份再分析**）
   - 内存/进程：截图进程列表、网络连接、计划任务
   - 时间点：记录每个关键动作的系统时间，用于对齐时间线
3. **入口封禁**：出口防火墙封禁恶意 IP/域名（回连地址、矿池、C2）。

> 红线：禁止在留证前清 history、删日志、覆盖文件。溯源全靠这些痕迹。

## 阶段 ③：三线排查

**目标**：找出恶意痕迹，确定失陷主机和恶意行为。

按事件类型打开对应 `知识库/` playbook + 对应排查清单（`ir-linux-checklist.md` / `ir-windows-checklist.md`），三线全过：
- **主机线**：进程、网络连接、启动项、计划任务、服务、账号、登录日志
- **Web 线**：accesslog、web 目录、中间件/框架配置、漏洞接口

**产出**：排查记录（命令 + 输出 + 结论），每条证据带时间点。

## 阶段 ④：溯源定因

**目标**：把「怎么进来的 → 干了什么 → 影响了谁」串成一条攻击链。

溯源要素：
- **入口点**：漏洞（web 漏洞/中间件漏洞/反序列化）？弱口令爆破？钓鱼/社工？供应链投毒？内网穿透？
- **攻击路径**：入口 → 跳板 → 目标（攻击路线图）
- **横向范围**：横向扫描、爆破、跨网段移动的证据
- **时间线**：把关键动作（上传、登录、执行、外联）按时间排序

**产出**：攻击路线图（文字版）+ 时间线。

> 高频场景：很多「新告警」其实是历史演习/历史入侵残留（如 22 年 HW 留下的计划任务在装 EDR 后才告警）。溯源时一定要**回溯历史应急报告和告警时间**，别把旧痕迹当新攻击。

## 阶段 ⑤：清除加固

**目标**：清除恶意项 + 堵住入口。

清除（确认恶意的才动）：
- 恶意文件、进程、计划任务、启动项、后门账号、ssh 公钥
- 重装系统（顽固/被远控深度控机的建议项）

加固（按根因对症下药）：
- 改弱口令、删无用账号、SSH 密钥认证、限制登录尝试
- 打补丁（如 MS17-010、中间件升级）、修漏洞接口
- 封禁恶意 IP/域名、关闭高危端口、网络隔离/ACL
- 装 EDR/杀软、全盘查杀、应用控制（禁 ProgramData/Temp 运行）

> 红线：**重装系统、删除数据、断网、封禁 IP 等不可逆或影响业务的操作，必须先经用户/客户书面确认**，默认给「建议 + 待确认」。

## 阶段 ⑥：出报告

按 `ir-report-format.md` 模板落报告。先给结论摘要，再出全文。

---

## 退出条件

- 恶意项已清除或已给出明确处置建议
- 攻击路径已串成时间线（入口点可定位则定位，定位不了要说明原因，如「日志被删」「时间久远」）
- 安全建议与根因一一对应，不是通用套话
