# 弱口令爆破 / 暴力破解应急响应

## 事件特征（分诊依据）

- 大量登录失败日志（SSH/RDP/SMB 爆破）
- 安全设备监测到主机对内网发起暴力破解攻击
- 弱口令账号被成功登录
- 多台主机同弱口令（如 password 为 111111/123456a!）

## 排查要点

1. **爆破来源定位**：查 auth.log/secure 的 Failed password，统计来源 IP 和爆破次数。
2. **爆破工具识别**：history/文件里找 haiduc（ssh 爆破工具）、masscan（端口扫描）、fscan（内网探测）。
3. **成功登录确认**：查 Accepted 记录、`last -i`、安全日志 EventID=4624/4625。
4. **弱口令范围排查**：检查 shadow 文件弱口令账号（如 inspur/123456a!）、系统账户密码为「1」等。
5. **入口点溯源**：
   - 对外暴露的 SSH 服务（非标准端口如 7712）
   - 内网穿透工具（ZeroTier/花生壳/远程映射脚本）把内网服务暴露到公网
   - 带后门的映射脚本（先创建后门账号再映射端口）
6. **横向范围**：爆破工具扫描日志（扫描网段、爆破次数、成功列表）。

## 典型攻击路径

### 路径一：公网直接爆破
```
对外暴露 SSH 服务（弱口令）
  → 公网爆破成功登录
  → 上传爆破/扫描工具
  → 内网横向爆破（多网段）
  → 多台弱口令主机失陷
```

### 路径二：内网穿透 + 后门脚本
```
学生/员工下载远程映射脚本（带后门）
  → 脚本先创建后门账号（fuckery/111111）再映射 22 端口到公网
  → 攻击者从公网爆破校内服务器（maxiaotian/111111）
  → 失陷后对内网弱口令爆破（57 台弱口令）
```

## 处置建议

1. 隔离失陷主机 + 封禁攻击 IP
2. 修改所有弱口令（强口令：8 位以上含大小写数字特殊字符至少 3 种）
3. 删除后门账号、无用账号
4. SSH 密钥认证替代密码、限制登录尝试次数、登录失败锁定
5. 关闭对外映射端口、拆除内网穿透（ZeroTier/花生壳/私自组网）
6. 最小化服务暴露、只保留必要端口

## 报告要点

- 事件分析重点：爆破来源、成功登录时间线、弱口令账号清单
- 总结给「失陷主机数 + 弱口令主机数」的影响面
- 建议对应根因：弱口令、内网穿透、对外暴露服务、安全意识

## 真实案例速记

- **北京工业大学弱口令**：张欣同下载远程映射脚本，脚本先在校外服务器创建 fuckery/111111，再映射 22 端口。攻击者爆破 maxiaotian/111111 登录 172.21.22.48，投 masscan 扫描 172.21.0.0/16，发现 57 台弱口令服务器。
- **北京工业大学数据删除（关联）**：ZeroTier 内网穿透 + 系统账户密码「1」+ ZeroTier 控制台弱口令 → 攻击者 SSH 登录删数据。
- **北京师范大学（关联）**：inspur/123456a! 弱口令 → haiduc 爆破 1300 IP → 16 台主机同弱口令失陷。
