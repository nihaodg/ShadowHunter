# webshell 网页后门应急响应

## 事件特征（分诊依据）

- EDR/云监控报 webshell 告警
- web 目录发现一句话木马、图片马、.jsp/.asp/.aspx/.php 后门
- 上传文件与告警时间吻合
- 网页被挂马/异常交互（响应包长度不一致）

## 排查要点

1. **告警文件定位**：拿到告警的文件路径（如 `/jboss/.../upload_xxx.tmp`、`nixi.jsp`），看文件内容确认是否为 webshell。
2. **webshell 类型识别**：
   - php 一句话木马、jsp 后门（天蝎/哥斯拉等）
   - 图片马（.jpg 里藏 php 一句话，通过文件上传漏洞打入）
   - .tmp 临时文件（文件上传/导入清单功能产生）
   - war 包里的 jsp 文件
3. **上传时间对齐**：webshell 创建时间 ↔ accesslog 里的上传接口请求时间 ↔ EDR 告警时间。
4. **漏洞入口判定**：
   - jeecg 任意文件上传漏洞 → 上传 jsp webshell
   - NC `bsh.servlet.BshServlet` 远程命令执行 → 上传 jsp
   - 蓝凌 OA 远程命令执行/组合漏洞
   - 任意文件读写/上传接口
   - Shiro 反序列化
5. **隐藏文件**：`dir /a:h`、`attrib` 显示隐藏文件；取消「隐藏受保护的操作系统文件」勾选。
6. **响应包交互判断**：请求 webshell 时响应包长度每次不一致 → 存在交互行为。
7. **历史残留排查**：跨年/历史演习留下的 webshell 未清除（对比历史应急报告）。

## 典型攻击路径

```
公网入口漏洞（jeecg上传/NC命令执行/蓝凌OA组合）
  → 上传 webshell 拿下入口机
  → 以入口机为跳板，利用内网中间件漏洞横向
  → 多台服务器上传 webshell
  → RDP/SSH 横向（抓取密码登录）
```

## 处置建议

1. 删除恶意 webshell 文件（不同工具交叉查杀：D盾、各种查杀工具）
2. 更新中间件/框架补丁（用友 NC、蓝凌 OA、jeecg、Shiro、jboss）
3. 全盘搜索其他后门（everything 按创建/修改时间搜）
4. 改账号密码、封禁攻击 IP、排查横向痕迹
5. 定期巡检杀毒、装 EDR

## 报告要点

- 事件分析按主机列，每台写：告警文件路径 + 文件类型 + 漏洞入口 + 上传时间
- 攻击路线图：多攻击者时分开列（如「攻击者A/B/C 三条路径」）
- 总结判断是否历史残留（22年HW痕迹）
- 建议对应根因：中间件漏洞、弱口令、未清理历史痕迹

## 真实案例速记

- **中航供应链**：EDR 报 2 台主机天蝎 webshell（.index.jsp、mrkaixin.jsp）。入口：jeecg 任意文件上传 + NC BshServlet 命令执行 + 蓝凌 OA 组合漏洞，三条攻击路径，均为 22 年 HW 残留。
- **长安保险**：阿里云 webshell 告警，涉及 6 台主机，文件类型多样（php 一句话 .tmp、war 包 jsp、图片马 .jpg、命令执行 .tmp）。MD5 去重后逐个定性，正常业务文件（泛微 OA 的 docOperation.jsp）不误删。
- **中航供应链反弹shell（关联）**：redis 未授权 → 添加计划任务反弹 shell 权限维持。
