# 数据删除 / 破坏应急响应

## 事件特征（分诊依据）

- 文件/数据丢失、被删除、被篡改
- 非本人操作（攻击者远程登录删数据）
- 账号信息被覆盖（admin 无法登录）
- 数据库数据被清空/锁定

## 排查要点

1. **登录溯源**：`last -i` 查非本地登录日志，定位攻击者 IP 和登录时间。
2. **删除操作日志**：auth.log 查 Accepted 记录，确认攻击者登录后执行删除。
3. **删除内容界定**：被删的是什么数据（个人训练数据 vs 核心业务/科研数据），判断危害程度。
4. **账号篡改**：admin 账号被覆盖的排查——
   - 查注册接口是否存在空参数 id 漏洞（id=1 覆盖 admin）
   - 区分「攻击」vs「漏扫脏数据」（漏扫工具给 id 赋值 1 触发覆盖）
5. **入口点**：
   - 内网穿透（ZeroTier）把内网服务暴露
   - 弱口令（系统账户密码「1」）
   - 无鉴权接口
6. **横向影响**：是否还有内网攻击行为（态势感知查告警）。

## 典型攻击路径

```
违规内网穿透（ZeroTier）+ 弱口令（密码「1」）
  → 攻击者（同 ZeroTier 网络）SSH 登录
  → 执行删除操作（个人训练数据）
  → 或漏扫工具触发注册接口 id=1 → 覆盖 admin 账号
```

## 处置建议

1. 封禁攻击 IP（防火墙/边界设备）
2. 重装受控服务器（彻底清除）+ 加固（补丁、关端口）
3. 拆除私自搭建的路由器/内网隧道（ZeroTier/翻墙）
4. 全面排查弱口令、强制复杂度 + 登录失败锁定
5. 数据恢复（备份/快照）
6. 全盘查杀、日志审计
7. 严禁账户外借、严禁翻墙、安全意识培训

## 报告要点

- 事件分析重点：登录溯源、删除内容界定、入口点判定（内网穿透 + 弱口令）
- 总结明确「被删数据性质」（是否涉及敏感/科研数据）
- 建议对应根因：内网穿透、弱口令、私自组网、违规外联

## 真实案例速记

- **北京工业大学数据删除**：科研服务器通过 ZeroTier 组网，系统账户密码「1」+ ZeroTier 控制台弱口令。攻击者 10.69.218.119 通过 SSH 登录删除数据（个人训练任务数据，未涉及科研代码）。首次登录 6 月 23 日 13 时。
- **中国农业大学 admin 丢失**：漏扫工具触发注册接口空参数 id 漏洞，id=1 覆盖 admin 账号。排查确认接口虽有鉴权但注册接口设计不合理（用户可传 id），另有 Shiro 反序列化高危漏洞。
